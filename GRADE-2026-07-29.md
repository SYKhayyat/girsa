## 0. Verdict

**Overall: C+.** The same letter the LiNix assessment landed on, for an almost opposite reason,
and the distance to a B is much shorter here.

What a user can rely on today: the two applications really do hand sources to each other over a
token-gated loopback, cross-process, byte-exact, with the ref preserved inside the document rather
than only the printed string. I verified that end to end with two live processes and `curl`, not
by reading about it. The security posture around it is the best-reasoned thing in the three repos
and it survived every adversarial probe I aimed at it.

What a user cannot rely on: **the quote that arrives has lost the edition it came from.** 6,211 of
the 7,189 works in this corpus send `"version":{}`. Three separate documents — `spec.md` §13,
`girsa-corpus::work::Work::version`, and `girsa-source`'s module note — say carrying provenance is
"the only thing preserving the option to distribute publicly later," and that a sefer typeset
without it "cannot be un-dropped." It is being dropped, right now, on the main path.

What nobody has looked at: **Girsa's CI has never run.** Not once. Neither has sefer-crates'. Both
repositories have no git remote, so `on: push` has never fired across 31 and 14 commits. That
includes the `dependents` job whose header comment calls it *"the job that pays for the
three-repository split"* — the gate that is the entire justification for splitting the shared
crates out of an atomic commit. And `app/src-tauri` — 4,501 lines holding the whole Girsa half of
the Ksav loop — is excluded from the cargo workspace and referenced by no gate anywhere.

The craft here is visibly higher than the codebase this rubric was written for. `unwrap_used` and
`expect_used` are denied workspace-wide, test names state properties instead of methods, and the
interop fixture was deliberately captured from the real producer rather than hand-written. The
grade is not about craft. It is about what has been *verified*, and the honest answer is that the
gates were built and then never switched on.

## 2. Findings

### N-1 — every Sefaria quote reaches Ksav with its provenance stripped — **blocker**

The edition is on disk and one directory away from the code that needed it.

```
$ cargo run -q -p girsa-app --example send -- corpus \
      "שולחן ערוך, אורח חיים סימן א' סעיף ג'" | tail -1
{"schema":1,"ref":"girsa:shulchan-arukh/orach-chayim/1:3",…,"version":{}}

$ cat corpus/works/shulchan-arukh/orach-chayim/work.json
{ "slug": "shulchan-arukh/orach-chayim",
  "version": { "edition": "Maginei Eretz: Shulchan Aruch Orach Chaim, Lemberg, 1893",
               "provenance": "https://www.sefaria.org/Shulchan_Arukh,_Orach_Chayim" } }

$ grep -m1 '^{"slug":"shulchan-arukh/orach-chayim"' corpus/works/index.jsonl
{…,"comp_date":"1563 CE"}          ← no version
```

**Root cause: two writers to one derived file, and they disagree.**
`crates/girsa-corpus/src/bin/girsa-import.rs`:

- line **95**, the default path: `write_index(&corpus_root, catalogue.works(), &catalogue)` —
  and `rewrite_metadata`'s own doc-comment says the catalogue *"does **not** know the printed
  edition: that is read out of the text when the text is read."*
- line **270**, the `--metadata-only` path: `work.version = on_disk.version` before pushing to
  `merged`, so this one preserves it.

`import::read` (`import/mod.rs:230-238`) sets `work.version` on a **clone**, which reaches the
per-work `work.json` and never reaches the catalogue slice. `Shelf::open`
(`crates/girsa-app/src/shelf.rs:112`) reads `works/index.jsonl` **and nothing else**.

**Scale, measured across the whole corpus:** 6,211 of 7,189 works. The 978 that survive are the
Otzaria-only ones, whose version the catalogue sets itself and so never had to make the trip.

**Why the guard did not catch it.** `sending.rs:577 provenance_travels_with_the_quote` asserts
`version.license == "Public Domain"` — against a `Work` it builds in memory with the version
already set. It asserts on the claim. `GRADER.md` §0.2 is exactly this rule.

**Family, checked rather than assumed.** I diffed every field of all 7,189 `work.json` files
against their `index.jsonl` lines. `version` is the **only** field dropped. The lossiness is one
field wide, which is good news and worth stating plainly.

**Failing tests:** `crates/girsa-app/tests/provenance_reaches_the_pen.rs` — 3 red, and I confirmed
2 of them go green when the defect is removed and red again when it is restored.

### N-2 — the one test that checks producer against consumer is asserting against history — **high**

`Ksav/ksav/engine/tests/from_girsa.rs` is unusually well-designed. Its module note explains that
unit tests "cannot prove the other half: that what the library actually puts on the clipboard is
what the pen actually reads," so the fixture is the real output of a real Girsa command. It then
warns: *"a fixture nobody can reproduce is a fixture that will be wrong quietly."*

It is wrong quietly. The committed `tests/fixtures/girsa-packet.json` carries edition and
provenance. Running the documented regeneration command produces `"version":{}`. So the check that
exists precisely to catch N-1 is comparing Ksav against a Girsa that no longer exists — and 8
tests pass on it.

This is the single highest-leverage fix in this document: make the fixture regenerate in the gate
instead of by hand, and N-1's whole family becomes impossible to reintroduce.

### N-3 — the gate that justifies the three-repository split has never executed — **high**

```
$ for d in Girsa Ksav sefer-crates; do (cd $d && git remote -v; git log --oneline | wc -l); done
Girsa:         (no remote)   31 commits
Ksav:          origin  https://github.com/SYKhayyat/ksav.git   (8 commits unpushed)
sefer-crates:  (no remote)   14 commits
```

`sefer-crates/.github/workflows/ci.yml` has a `dependents` job that checks out Girsa and Ksav and
builds both against the proposed change. Its comment is right about why it must exist:

> Girsa and Ksav each pin an exact version of these crates, so a breaking change here cannot be
> caught by either app's own CI until someone bumps the pin — which could be weeks.

With no remote, `on: push` has never fired. So across 45 commits in two repositories, nothing has
ever run `cargo fmt --check` on Linux, `clippy` on Linux, or that job. The three-repo design traded
one atomic commit that compile-checks both applications for a CI gate — and the gate was never
turned on. Ksav's own CI file says this out loud about its past (*"since there was no remote at
all, not even that"*) and is now the only one of the three that could be running.

Fix cost: two `git remote add` commands and a push. It is the cheapest high finding here.

### N-4 — 4,501 lines holding the whole Girsa half of the Ksav loop are in no gate and have no tests — **high**

```
$ wc -l app/src-tauri/src/*.rs        → 4,501 total (lib.rs alone 4,080)
$ grep -c '#\[test\]' app/src-tauri/src/*.rs   → 0, 0, 0, 0
$ grep -c src-tauri .github/workflows/ci.yml   → 0
$ grep -c src-tauri ../sefer-crates/tools/check-dependents.sh → 0
```

`Cargo.toml` excludes it from the workspace deliberately and explains why (it cannot build until
the frontend is in `app/dist`) — which is a real constraint and the wrong conclusion. The result is
that `cargo build --all-targets` at the root, *"the check every work order has to keep green"*,
cannot see: `Desk::open`, `send_to_ksav`, `ksav_presence`, the deep-link handler, the layered
clipboard, and 91 tauri commands. Every headline claim in `spec.md` §10 is implemented in the one
directory no gate looks at.

**In fairness, and checked rather than assumed:** I compiled it.

```
$ cd app/src-tauri && cargo check --all-targets
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 2m 11s      # 0 warnings
```

It is `fmt`-clean, `unsafe_code = "forbid"`, and has exactly **one** `unwrap`/`expect` site in
4,080 lines — though note the workspace's `clippy::unwrap_used = "deny"` does **not** reach here,
so that was discipline, not enforcement. So this is not "probably bad code": it is healthy today
and *nothing keeps it that way*. Which is the narrower and more accurate complaint — one refactor
in a shared crate breaks it and the first person to find out is a user. Ksav, by contrast, does
gate its shell (358 lines, 3 tests, in CI).

The 2m11s is also the reason it was excluded, and the answer to it: cache the target directory and
it is a `needs:` edge behind the frontend build, not an exemption.

### N-5 — a torn catalogue line removes seforim from the library in silence — **medium**

Reproduced with a three-line `index.jsonl` whose middle line was cut off mid-write:

```
$ girsa-shelf <that corpus>
 תנ״ך  1 …
3 shelves · 4 seforim counted of 4 on the shelf
$ echo $?
0
```

No mention of the bad line, anywhere, at any verbosity. `shelf.rs:640`:

```rust
.filter_map(|l| serde_json::from_str::<Work>(l).ok())     // dropped on the floor
```

The asymmetry is the finding. In the *same function*, `Shelf::open` collects bad lines from
corrections, link repairs, scans, notes, marks, saved queries and collections, and folds all of
them into `trouble()`, with a comment saying *"A correction that will not read is one correction,
and it is said out loud."* The corpus catalogue — the file that decides which seforim exist at all
— is the one loader exempted from the rule that the rest of the function is built on.

Note the shape of the reassuring line too: *"4 seforim counted of 4 on the shelf"* counts what it
loaded against what it loaded. It reads as a self-check and cannot fail. `spec.md` §5 promises the
opposite: *"Nothing is ever missing, and 'is it in there?' stops being a question you have to think
about."*

**Failing tests:** `crates/girsa-app/tests/a_sefer_never_vanishes_quietly.rs` — 2 red.

### N-6 — `ksav serve` reports a pairing with Girsa that does not exist, at its own address — **medium**

```
$ GIRSA_POST_HOME=<empty scratch dir> ksav serve 127.0.0.1:7911
Ksav editor serving on http://127.0.0.1:7911 (16 workers)
paired with Girsa on 127.0.0.1:59619
$ cat <scratch>/ksav-endpoint.json
{ "app": "ksav", "port": 59619, … }        ← that is Ksav's own port
$ ls <scratch>                              ← there is no girsa-endpoint.json. No Girsa is running.
```

`engine/src/server.rs:315` prints `desk.port()`, where `desk` is Ksav's own desk. It should say
*listening for Girsa on …*; whether Girsa is there is a separate question that `post::girsa()`
answers correctly. This inverts the §10.6 promise — presence exists so *"the affordance is never
offered when it would fail"* — into telling the user their sibling is present when it is not.

### N-7 — Ksav's tree is unformatted and its CI asks for `rustfmt` and never uses it — **medium**

```
$ cd Ksav/ksav/engine && cargo fmt -- --check | grep -c '^Diff in'
110
$ grep -rn 'cargo fmt' Ksav/.github/                → no matches
$ grep -rn 'rustfmt'   Ksav/.github/                → ci.yml:57  components: clippy, rustfmt
```

The component is installed and never invoked. Girsa's CI *does* gate on `cargo fmt --check`. So two
halves of one product disagree about whether formatting is a gate, and the half with the working
remote is the unformatted one. `check-dependents.sh` runs neither `clippy` nor `fmt` on dependents,
so nothing else catches it either.

### N-8 — `{"taken":true}` is a promise Ksav cannot keep — **medium**

```
$ curl -X POST -H "X-Girsa-Token: $TOK" --data-binary @packet.json .../insert
{"taken":true}
$ taskkill /F /PID <ksav>          # the writer closes the window before the editor polled
SUCCESS: The process with PID 39896 has been terminated.
```

The source is gone. `engine/src/post.rs:65` is `static INBOX: Mutex<Vec<Arrival>>` — no cap, no
persistence — drained only when the editor polls `GET /inbox`. Girsa was told the source arrived
and has no way to learn otherwise.

The doc-comment there rejects a channel because *"a channel that nothing is reading from while the
window is closed is a channel that either blocks the sender or throws the source away."* The `Vec`
also throws the source away — just at process exit instead of immediately — and grows without
bound in the meantime. §10's design target is AirDrop; AirDrop does not lose the file when you
close the window.

## 3. What held up, checked adversarially rather than assumed

`GRADER.md` §3 says finding nothing new means not looking hard enough. The converse also deserves
recording: these are the things I attacked and could not break.

**The loopback's token discipline — verified cross-process, not by reading it.** Two live
processes, real HTTP:

```
/health with no token                        → 401
/health with the token                       → 200 {"app":"ksav","version":"0.1.0"}
/insert with a wrong token                   → 401
/insert with the real packet and real token  → 200 {"taken":true}
CORS / Access-Control headers in any reply   → none
```

Every claim in `girsa-post`'s module note is true, including the subtle ones: the token is required
on `/health` too, it travels in a header rather than a URL, and no preflight is answered. This is
the best-reasoned code in the three repositories.

**The schema-version refusal is real, and it is the model for how the rest should behave.**

```
$ curl -X POST -H "X-Girsa-Token: $TOK" --data '{"schema":99,…}' .../insert
{"error":"this packet is schema v99; this build understands up to v1. Update Ksav, or send from a matching Girsa."}
http=400
```

Names both versions, names the two things the user can do, one place to look. That is `GRADER.md`
§4's rule met exactly, and it is met nowhere else as cleanly.

**Presence correctly disbelieves its own endpoint file.** I killed Ksav with `taskkill /F`, so
`Desk::drop` never ran and the stale endpoint file was left behind — the exact case the doc claims
to handle. Probed with a throwaway crate outside all three repos:

```
ksav:  Stale { why: "could not reach ksav: connection timed out" }
girsa: NotRunning
```

`presence()` reads the file and then *asks* it, and distinguishes "no file", "nobody answers", and
"something else answered on that port". Correct.

**Packet fidelity through the loopback is byte-exact, and the ref survives into the document.**

```
replacement char U+FFFD in reply : False
text verbatim inside markup      : True
display verbatim inside markup   : True
ref preserved in markup          : True
```

The arrival is `#ציטוט[…]#מראה_מקום(מקור: "girsa:shulchan-arukh/orach-chayim/1:3")[…]` — the ref
stored in the document rather than only the printed string, which is the claim §10.2 says no
paste-based workflow can ever match. It is true.

**The shared crate is genuinely shared, not a documented JSON shape.** sefer-crates is compiled
into both applications, pinned `=0.4.0` by exact version on both sides, with `path` to the sibling
checkout. This is the load-bearing architectural claim of the whole product and it holds
structurally.

**Ksav really typesets.** A hand-written `.ksav` produced a real PDF and SVG; a document with an
unclosed delimiter produced `[error] unclosed delimiter` and exit **1**; a missing input produced
exit **2**. Exit codes on the real paths are correct, which is more than the codebase this rubric
came from managed.

**The wasm CI job runs the engine rather than merely linking it** — it compiles every bundled
template through the wasm build and checks the spell-checker answers, with a comment explaining
that a binary which instantiates and then panics on first use would pass every earlier step. That
is precisely the discipline `GRADER.md` was written to demand, arrived at independently.

**The spec's ground truth is real.** §2.1 claims were verified against the actual files: float line
indices, the misspelled `"Conection Type"` key, stale `path_2`, 74% untyped links. All confirmed.
Specs that were checked against data before being written are rarer than they should be.

## 4. What I could not test, and what it would take

Reported in the negative, per `GRADER.md` §0.3. A report with no such list is incomplete, not clean.

- **Linux and macOS: nothing.** Everything here ran on Windows 11. Two of the three repos have
  never been compiled on any other platform by anything but a person. Needs: a remote, a push, and
  ~20 minutes of Actions.
- **The Tauri desktop apps as applications.** I drove `ksav serve`, the engine CLI, all 14 Girsa
  binaries, and the loopback — but not either windowed app. So the layered clipboard's three
  flavours (§10.2) are verified as *produced* by `girsa-app`, never as *pasted* into Word or
  WhatsApp. Needs a desktop session and a human at the keyboard.
- **`girsa-lane`, the semantic lane.** 39 tests, and the real path needs a 709 MB BEREL model I did
  not fetch. Untested for real by me or, as far as I can tell, by anyone.
- **Deep links** (`girsa://`, `ksav://`). Handler code exists on both sides; exercising it needs OS
  protocol registration, which means installing the apps.
- **A real pty.** `GRADER.md` §4 asks for it and I did not do it — everything I ran had pipes on at
  least one handle. In mitigation: none of these binaries emit ANSI escapes at all
  (`ESC sequences down a pipe: 0`), so the class of bug pty testing exists to catch has less
  surface here than in a tool that colours its output.
- **First-run download.** §5 promises a resumable ~5 GB first run. This checkout already has a
  populated corpus and index, so I tested the steady state, not onboarding. That is the single
  biggest untested user-facing path in Girsa.
- **`--metadata-only` as the N-1 workaround.** I did not run it against the real corpus, because
  doing so would have rewritten 7,189 files and destroyed my own reproduction. It appears from the
  code that it would repair `index.jsonl`; that is a reading, not a result.
- **Property/model-based tests and the crash-recovery family** (`GRADER.md` §5–§6). Neither exists
  in any of the three repos, and I did not build them.

## 5. Four corrections to my own method

Recorded because the failure mode this rubric is about is *checks that examine the wrong thing and
then report success*, and mine did it four times in one session.

1. **I read `tail -60` of a test log and reported 7 tests for a nine-crate workspace.** That was one
   binary's output; the truncation ate the rest. The real number is **617**. I nearly opened with a
   finding that the project had almost no tests.
2. **I took `$?` after piping into `head`, twice**, and concluded that usage errors exit 0 — a
   plausible, damning, entirely fabricated finding. They exit 2.
3. **I saw Hebrew return from the loopback as `????` and nearly filed a corruption blocker.** It was
   my own terminal's cp1252 stdout; a byte-level check showed the payload is exact. The tell was
   that the Hebrew *command names* rendered while the Hebrew *content* did not — which made no
   sense as a data bug and complete sense as a display bug.
4. **I flagged `taxonomy.rs:267 version: None` as the production defect.** It is a test helper. And
   I concluded `ksav serve` never opens a loopback desk because it was not in `main.rs`; it is in
   `server.rs:313`.

Every one of those was an assertion against a system in the wrong state, and every one failed
toward a false positive. If this report has a fifth of them, it is in the parts where I reasoned
from code rather than running something — which is why §4 exists.

**Why the test infrastructure is a D+ and not the D− its predecessor earned.** I went looking for
assertions that cannot fail — the thing that made LiNix's harness worse than no harness — and found
none. What I found instead is gates that never *ran*. That is a genuinely better failure: a check
that lies is invisible, while a CI that has never fired is discoverable with `git remote -v` and
fixable in a minute. The stale fixture in N-2 is the one item that crosses into the lying category,
and its own author wrote the warning about it into the file.

**Why the overall is C+ when most areas are B or better.** The rubric's C bar is *"builds, tests
green, core safety paths correct, breadth largely unverified"* — which describes this exactly. B
requires every blocker fixed and local gates matching CI; there is a live blocker and there is no
CI. The engineering argues for a B+; the verification argues for a C. The rubric grades
verification, and it should.

### What moves each area up one letter
