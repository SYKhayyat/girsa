# Girsa — lamdan, 6 August 2026

A design argument, not a bug hunt. The question is not whether the code works;
it is whether this was the right thing to build, whether it is the right shape,
and whether the right things are inside that shape.

Full sweep: ten regions, every tracked file read by someone. Excluded and named:
`Cargo.lock` ×2, `app/package-lock.json`, four icon binaries, `LICENSE`,
`LICENSE-MIT`, `LICENSE-APACHE`, `licenses/Apache-2.0.txt`.

---

## The claim, first

**§3 is not implemented at the one moment it exists for.**

`spec.md` §3 calls permanent segment IDs *"the single most important decision in
this document"* and *"close to impossible to retrofit."* Decision 2 settles it.
`BUILDER.md:266`, `segment.rs:208` and `store.rs:198` each promise a redirect
table that absorbs upstream re-segmentation.

Three facts, verified directly:

1. `import::write` (`crates/girsa-corpus/src/import/mod.rs:411`) emits exactly
   two files — `work.json` and `segments.jsonl`. **There is no slot on disk for
   a redirect table.** A `SegmentStore` round-tripped through disk loses every
   redirect it holds.
2. `SegmentStore::import` (`store.rs:134`) assigns `Ordinal::root(i + 1)` from
   enumeration position. Its doc says *"it happens once in the life of a work."*
   That is a claim about the world, not about the code: `girsa-import` runs
   `import_all` over the whole catalogue on every invocation, and `write` is an
   unconditional `fs::write`.
3. `SegmentStore::redirect` has three callers. All three are in
   `tests/anchors_survive_editing.rs`. Its doc comment says *"The importer calls
   this."* The importer does not.

So: Sefaria adds one se'if to siman 1 of Orach Chayim, you re-run `girsa-import`,
and 4,170 segments renumber by one. Not a broken link — **the wrong text,
silently**, which is T1 verbatim, at import granularity instead of line
granularity. The permanence property holds exactly as long as you never
re-import, and the tool is called `girsa-import`.

`--metadata-only` exists precisely because someone expected to re-run the
importer. Somebody noticed re-importing was expensive. Nobody noticed it was
also destructive.

**Steelman, and half of it holds.** Within a single import the split case *is*
absorbed without a table: the oversized cutter mints `#32.1`/`#32.2` and
`Ordinal::covers` makes `#32` name all of them. That is genuinely clever and it
is why nothing has broken yet. It also only covers splits *this importer
performs deterministically*. It does not cover upstream re-segmentation, which
is the case §3 was written about and the case that actually happens.

The other steelman — *you would re-import from scratch and re-anchor by hand* —
does not survive contact with the product. Anchors live in Ksav documents on
somebody else's disk. There is nothing to re-anchor by hand.

**Verdict: `rewrite`.**
**The change:** `redirects.jsonl` beside `segments.jsonl`. `import::write` writes
it, `import::read_back` reads it, `import_all` reads the previous run's ids
before minting new ones.
**The first commit is cheap and should happen today:** make `write`/`read_back`
round-trip a `redirects` field that is empty for every work. The format then has
the slot before it needs it. Doing this after the next corpus update is
retrofitting exactly the thing the spec says cannot be retrofitted.
**Cost:** additive, empty today, 7,189 directories. Near zero now; unbounded
later.

### And the reason nobody caught it

`crates/girsa-corpus/tests/spec_counts.rs` is the test that would have. It is one
of **36 test functions across 12 files** that gate on a corpus being present and
`return` when it is not:

```rust
macro_rules! corpus_or_skip {
    () => { match corpus() { Some(root) => root,
        None => { eprintln!("skipped: no imported corpus"); return; } } }
}
```

`cargo test` captures stderr on passing tests. In CI these print:

```
running 2 tests
test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; finished in 0.00s
```

Two green tests, 0.00 s, having asserted nothing about anything. `#[ignore]`
would at least print `2 ignored`.

Twelve files away, `tools/check-ksav-fixture.sh:41` refuses this by name:

```sh
# Not a skip. A check that passes because it could not find what it checks is
# the exact failure this script exists to end.
```

The rule is written down, correctly, in this repository, and 36 test functions in
the same repository do the thing it forbids. **This is the pattern the rest of
this document is about.**

The fix already exists in-repo and was applied once.
`crates/girsa-app/examples/fixture-packet.rs` builds the one work its fixture
needs from constants in a temp directory, because *"regenerating it needed a
corpus no gate has. So the corpus is the thing that had to go."* That argument
generalises verbatim to all 36. It was applied at n=1 and stopped.

**Verdict: `rewrite`. Change:** a synthetic ~20-work fixture builder, on the
`fixture-packet.rs` model. **Cost:** ~200 lines, once.

## Lens 1 — was this the right software?

### Where my own sketch lost, and I concede it

Before reading, I committed to: *one crate, one store, one index, one CLI, a
webview that is a dumb projection; links, scans, embeddings and MCP deferred
until the writing loop had been used in anger for a month.*

Three of those four deferrals were wrong, and the code refuted them:

- **Links should not have been deferred.** Resolving 5.1M citation-addressed rows
  onto permanent ids, with `Unsettled` written out rather than dropped
  (`sefaria.rs:130`), is the most valuable single artifact in this repository and
  nobody else has it. The Meilah disambiguation — *a candidate is eliminated only
  when the shelf can refute it* — is a real epistemic rule, correctly applied
  twice in two subsystems.
- **Paging should not have been deferred.** `girsa-scan/src/paging.rs` is ~150
  lines, depends on almost nothing, makes a scan citable with no OCR and no
  model, and its anchor-list design is the best decision in the repository: a
  single offset cannot re-point citations already written, which is the Otzaria
  line-index defect one level up.
- **The lane's cost when off is genuinely zero**, and the discipline around it —
  its own type that cannot merge with `Hit`, never a rung on the ladder, coverage
  stated in every answer — is better than the thing it guards.

The sketch survives in exactly one place, and it is the one that matters: **the
derived state should have been deferred until the readers that consume it
existed.**

### The derived state outweighs the truth 2:1

Measured on disk: `corpus/links` is **1.8 GB live plus a 1.6 GB
`links.superseded`** the orient tool left behind.

| | size | files | what it is |
|---|---|---|---|
| `edges.jsonl` | 664.7 MB | 6,185 | the truth |
| `inbound.jsonl` | 656.4 MB | 5,317 | cache |
| `touching.jsonl` | 448.7 MB | 6,268 | cache |

**`touching.jsonl` — `delete`, replace with a bitmask.** Its only in-repo
consumer is `girsa-index.rs:340`, which calls `touching::by_segment`, which
destructures `(anchor, edge_type, _)` — **throwing away the `w` field W31 grew
the file for**. The output is `Vec<BTreeSet<EdgeType>>`: nine bits per segment,
consumed once at index-build time. 449 MB across 6,268 files exists to produce
under ten megabytes of facet bits. One byte per segment in reading order is ~4 KB
for Shulchan Arukh Orach Chayim instead of 4.14 MB.

The steelman — *the `w` field is for OtzariaSonim, a phone reader, and the corpus
is a shared contract* — fails twice. First, this repo's own answer to the same
question (`girsa-app/src/mefarshim.rs`) reads `inbound.jsonl` instead and doesn't
need `w`. Second, `mefarshim.rs:18` records what the phone already does: *"a
bitmap per commentator — one bit per line."* Building an external app's cache is
defensible; building it ~12× larger than the shape that app already uses is not.

**The rule that caused the thing it forbade.** §8.2 — *"the inverse is derived
and never stored twice"* — is a **truth** rule: don't let two copies disagree. It
was implemented as a **storage-layout** rule: edges live only in the `from`
work's shard. Every consumer needs the inverse, so the inverse got stored anyway,
in caches, and the edge is now on disk **four times**. The rule against storing
it twice is why it is stored four times, and why there is a 98-second batch job,
a `built` marker, and `incoming_unknown` threaded out to the UI.

**`Row.edge_type` — `delete`.** `store::read_edges` (`store.rs:187`) recomputes
`edge_type` from `row.label` and ignores the field it just parsed. Nothing in the
workspace reads `store::Row::edge_type`. So `"type":"references",` — 20 bytes — is
written 4.18M times into `edges.jsonl` and 4.18M times into `inbound.jsonl`.
About **170 MB of a 1.3 GB pair is a field no code reads**, which grep presents
as authoritative, and which the next typing pass would write and every reader
would ignore.

### The uncertainty it does not report is its own

This is the codebase that invented `Refused.incoming_unknown`, `Found::NotWithin`
vs `Found::None`, `w` empty meaning *"this row does not say"* rather than
*"nothing"*, and the `built` marker so a missing cache is never read as a zero.

`orient.rs:93` computes `Orientation::Undeclared` for **2,039 works**, counts it,
prints it in one log line, and throws it away. An edge whose direction the corpus
declared and an edge whose direction is the accident of a CSV column order are
byte-identical on disk and score identical `confidence()` — `Method::confidence`
knows only which corpus it came from.

**Verdict: `rewrite`.** One byte on the row beside `method`; `Repaired::confidence`
reads it. **Cost:** a format field and a cache rebuild — which is why it should
have gone in when the format was minted.

### Two artifacts sharing a word

A scan-as-sefer and a text-sefer are unified at the id layer (one `SegmentKind::Page`
segment per page), which is right and cheap. Then every consumer buys the
difference back: `girsa_app::is_scan`, `Hit::is_a_page`, `Hit::is_scanned`,
`Hit::by`, `Writer::add_page` vs `Writer::add`, `ScanView` vs the reading pane,
`scanning::mareh_makom`. Six predicates and two write paths to preserve the
fiction.

**One index is still right** — two indices means every query runs twice and
merging two rankings is a new decision with no principled answer. What is wrong
is narrower: `Writer::add_page` (`index.rs:1820`) writes `read.text()` into the
same field as corpus text, so **the index holds a copy of a personal-layer
artifact**. `Words::page` applies corrections at read time; the index does not.
Correct a word on a scan and you cannot find what you fixed, and you can still
find what you unfixed. `wrong-but-keep` only if scans are rare; `rewrite` the
moment anyone OCRs a masechta.

### The lane's measurement is at n=240 and it is offered at n=5,000,545

`model.rs:56` measures over Hilchos Tefillah: 240 se'ifim. Top-16-of-240 every
time, first 8 times in 10. `adjacent.rs:41` gives the spread: top hit at cosine
0.74 against unrelated se'ifim at 0.63.

**A 0.11 margin over 240 candidates is a different claim from a 0.11 margin over
10⁵.** At 240 the tail is empty. At 100,000, the tail *is* the answer set.

The crate names its other limits with real rigour — throughput, the
question-vs-statement asymmetry, mean-centring tried and rejected on evidence. It
does not name the scale problem at all. And then `Chosen::everything()` is
offered as a first-class standing choice, and `Coverage::said` has a *tested*
branch for *"this lane covers the whole library — 1,200,000 of 5,000,545 so far."*
The unmeasured 13-day configuration is offered as an equal option to the measured
54-second one, with nothing anywhere saying which one the numbers came from.

**Verdict: `wrong-but-keep`, with one change.** Either `everything` carries the
thirteen days in the sentence that offers it, or re-run `examples/measure.rs` at
50k before `ask()` keeps its UI. **Cost:** one sentence, or one afternoon.

**And `delete`, separately:** roughly **250 lines of `model.rs` are a hand-written
BERT forward pass** (`Embeddings` 633-686, `Layer` 688-770, `Model::run` 395-440).
`candle-core` and `candle-nn` are in the lockfile; `candle-transformers` — same
crate family, same version, has this — is not, and nothing anywhere explains why.
Also `delete`: `bring.rs`, 356 lines of resumable-with-Range HTTP guarding a
button a fresh install cannot see, for a model the crate insists is
interchangeable with any BERT in a directory.

### `chain.rs` — 1,052 lines a reader cannot reach

`grep -i chain app/src/*.ts` returns nothing. There is no chain view. The only
callers are a developer CLI and `girsa-mcp`.

The ideas in it are the best epistemics in the codebase — *direction is time, not
the arrow*; `NotWithin` vs `None`; `Trace::is_transmission` false the moment one
hop is `References` given that 49% of the graph is `References`; `Fork` refusing
to say two seforim disagree when the corpus has zero `disputes` edges. None of
that is padding.

But `inbound.rs:12` states it plainly: the 200-shard walk *"is affordable for a
sidebar… It is not affordable for W28."* **Chain is why the cache holds whole
edge rows rather than a summary, and why `Graph::work` is an eager whole-work
load.** A feature no reader can reach set the memory shape of the feature every
reader uses.

Given decision 18 I will not call it wrong to exist. It was wrong to build
*before* the sidebar it slowed down had been used in anger. **`wrong-but-keep`.**

### MCP is not in the spec

`girsa-mcp/src/lib.rs:5` cites §12 for *"MCP on both ends."* §12 is Architecture —
crates, repos, platforms, Tauri — and contains **no mention of MCP**. The only
occurrence of the string in `spec.md` is one word in the M8 milestone list at line
886. The place where a program *does* talk to Girsa is §10.6, which is loopback,
token-gated, Source Packet, and explicitly not this.

Delete the crate and nothing in Girsa breaks, nothing in Ksav breaks, no test
outside it fails. It is the only pure leaf in the tree.

**But it earns itself on one condition and I concede it:** `Server` holds the
tantivy index, catalogue and timeline open for the process's life, which a
per-invocation CLI cannot give an agent making forty calls. **`wrong-but-keep`.**

Two things worth saying anyway. First: **this is interface number sixteen.** The
tree ships fifteen binaries, none sharing an argument-parsing layer or an output
layer; five of them parse argv five different ways and disagree about their own
positional prefix. MCP is the sixteenth symptom, not the offender. Second, and
more diagnostic: **the best and most honest writing about the semantic lane's
limits anywhere in this repository is a tool description for a robot** —
`tools.rs:211`, *"Measured to work on a half-remembered statement and to work
poorly on a question. It does not pasken."* Not in the lane's own UI.

### The artifact that should not exist as maintained: the README

2,549 lines. **The highest-churn file in the repository** — 29 of 59 commits
touched it — hand-maintained, and already false. It says *"a window and fifty
commands."* `grep -c '#\[tauri::command\]'` returns **100**. `ci.yml:66` and
`GRADE:99` both say 91, which was true at the grade and is 11% stale.

I tried to produce a split and could not make one survive the project's own
criteria — see *What I could not beat*. What I will say without hedging: 92% of
the file is design rationale and lab notebook, and **70 lines are a builder's
W-number index living in a reader's document**. That is the cut to try, and it is
not the pasted output.

**`wrong-but-keep` on the content. `rewrite` on the maintenance:** the numbers in
it are hand-typed and there is no gate. `docs/shortcuts.md` is the model — the
repo already owns generate-and-diff in `tools/check-ksav-fixture.sh` and applied
it to Ksav's packet and not to its own card.

## Lens 2 — is this the right shape?

### The finding

**This codebase reliably wins the argument it is having, and reliably does not
notice it has had the argument before.**

Three sweeps that never spoke to each other arrived at this independently. The
evidence is not stylistic; every instance below is a doc comment that states an
invariant, next to a caller that violates it.

| The rule, written down in this repo | What the caller actually does |
|---|---|
| `store.rs:198` "The importer calls this" | It doesn't. Three callers, all tests. |
| `work.rs:213` "**This is the same function** the lexicon is built with… a second implementation that drifted by a hyphen would resolve citations onto works that do not exist" | `examples/build-lexicon.rs:156` is a second implementation. So is the comment. |
| `since.rs:178` "Shared, so a search panel that finds an index and one that does not cannot be two answers to one question" | `lib.rs:855` is a second `find_index` with a **different accept predicate** — and both are called from that same file, forty lines apart. |
| `index.rs:1013` `Prepared` is built once and asked three times, because "a facet computed from a differently-built copy would be a column of numbers that did not add up" | `bar.rs:204` and `:206` each build it. Smart builds it three times. |
| `beside.rs:110` "Built once per pair of open panes" | `lib.rs:3609` builds it per scroll event, reading both works' multi-MB shards. |
| `session.rs:224` "Clamped in **one** place, here, rather than in the window and again in the command" | `set_text_size` clamps inline 68 lines later; the clamp that actually matters (15–85%) exists **only** in `layout.ts:78`. |
| `torat_emet.rs:196` "two descriptions of one rule drift" | `Found::marks` and `Marker::Widened` are character-identical and both live. |
| `settingsview.ts:11` names the clamp duplication as a defect | commits it 106 lines later. |
| `fix/lib.rs:63` `Kind::as_str` exists to prevent wire-format drift | the same enum also derives `Serialize` with `rename_all`. Two spellings of one wire format on one type. |
| `check-ksav-fixture.sh:41` "a check that passes because it could not find what it checks is the exact failure this script exists to end" | 36 test functions do exactly that. |

And the same idea, invented from scratch, repeatedly:

- **Three** append-only-log-keyed-by-subject implementations — `girsa_scan::Words`,
  `girsa_lane::Vectors`, and two `Job` types — each citing W8's doubled graph as
  its justification, two of them sharing a **verbatim doc paragraph**.
- **Six** copies of write-temp-then-rename: `girsa-fix/lib.rs:562`,
  `girsa-fix/suspect.rs:605`, `girsa-note/mark.rs:478`, `query.rs:284`,
  `collection.rs:340`, `girsa-link/repair.rs:416` — plus `girsa-scan/store.rs`,
  `girsa-lane/lane.rs`, `chosen.rs`.
- **Three** "what this answer could not see" composers — `Coverage::said`,
  `reading::Gap`, `since::Unindexed::said` — each documented as composed *once so
  the surfaces cannot drift*, and drifting from each other: a `search` answer
  carries `did_not_search`, an `adjacent` answer carries `coverage`, nothing
  composes the two.
- **Four** "describe a segment for a surface" composers: `girsa_app::Near`,
  `HitRow`, `mcp::named()`, and per-bin printing.
- **Four** re-anchoring predicates for one rule: `Notes::touching` uses
  `on.covers(at)`; `Marks::on` uses both directions; `Collection::holds` uses one;
  **`Layer::on` uses exact equality** (`fix/lib.rs:412`). So a correction made
  before the corpus splits its segment stops applying — silently, with no `stale`
  report, because the patch is never even looked up.
- **Three** HTML escapers, two byte-identical (`sending.rs:338` / `scanning.rs:205`)
  including a five-line comment about gershayim that now exists twice and can rot
  in one.
- **Eight** independent implementations of "a panel" across **three** mechanisms
  (`hidden` attribute, `is-open` class, `width: 0` transition), which is why
  `main.ts:961` contains 48 hand-written lines of Escape and focus routing that
  must know which mechanism each panel uses.
- **Five** argv parsers across the bins, disagreeing about their own positional
  prefix.

### Why it happens, and it is not carelessness

`git log`: **98,488 insertions against 2,334 deletions**, 59 commits, four
calendar days. W9 alone is 11,026 insertions in one commit. A 42:1 ratio.

Nothing here has ever been taken back. Each work order was a fresh pass that
solved its problem correctly, in isolation, and wrote down eloquently why its
solution was right. Not one of the 59 commits went back to notice that the
previous six passes had solved the same problem. **The design lives in prose, and
prose is not checkable.** Every invariant in the table above was written down
beautifully — and writing it down was mistaken for enforcing it.

That is the diagnosis, and it is why the single highest-leverage change in this
repository is not any individual fix below. It is turning three or four of those
doc comments into tests.

### The wire format is described four times, one of them untyped

1. `girsa-app` model types — Rust, checked.
2. `app/src-tauri/src/lib.rs` — 52 structs, 637 lines, Rust, checked.
3. `app/src/api.ts` — 59 TypeScript interfaces, hand-mirrored, **nothing verifies
   they agree**.
4. `crates/girsa-app/examples/dev-fixtures.rs` — the one tool whose entire job is
   to emit the same JSON, and it **cannot** import (2), because `girsa-app`
   cannot depend on the shell. So it rebuilds the shapes with `serde_json::json!`
   by hand. **A field renamed in `lib.rs` compiles clean, ships, and the browser
   fixture path — the exact path W9's cross-engine trap exists to exercise —
   silently serves the old shape.**

That fourth copy is the proof the DTOs are in the wrong crate. The codebase
already does the right thing for 14 model types that cross IPC untranslated
(`Companion`, `Branch`, `Place`, `Relation`, `Look`, `Press`, `Presence`,
`Facets`, `Chip`, `Session`, …) and stopped.

**Verdict: `rewrite`. The change:** `crates/girsa-app/src/view.rs` — every
`#[derive(Serialize)]` row the window draws, with its `of()` constructor, in the
crate that owns the facts. The shell becomes ~100 functions of the shape *lock,
call `view::X::of(…)`, return*; 23 already are. Estimated shell after: 900–1,200
lines from 4,590. `dev-fixtures.rs` then imports real types.
**Cost:** mechanical, ~600 lines moved, no behaviour change. Seven structs
genuinely can't move (they need `girsa-search`, which `girsa-app` doesn't depend
on) and they'd be the visible exceptions instead of the invisible rule.

### The README's central thesis is false in one load-bearing place

> *"`app/` is the Tauri shell: a window and fifty commands, and **nothing that
> decides anything**. Where a pane lands … [is] answered in `girsa-app`."*

Measured: of 4,590 lines, **~23 commands / ~150 lines are genuine pass-through —
4%**. The shell decides cache policy (`KEEP_OPEN = 12`, and it's FIFO not LRU,
so a hit never refreshes), sort orders, truncation lengths (90 chars, 120 chars,
40, 25), path search order, patch provenance (`who()` → `USERNAME`/`USER`/`"me"`,
written into every patch file handed to another person), a ten-item font list,
and default-on-unknown for four chip families (`set_chip` silently falls back;
`link_repair` forty lines away errors — two policies, one file).

And the claim's own example: **`lib.rs:3583-3608` is a complete parallel
implementation of W9's placement rule for scan followers.** It computes
`Place::At`/`NoPlace`/`Unrelated` by hand and synthesises
`Relation::Declared { follower_is_commentary: false }` out of nothing.
`Beside::between` — the tested one — is reached only in the `else` at `:3609`.
A scan beside a Gemara is exactly the case W9 was accepted on, and it never
touches the tested path.

**The thesis is right; the boundary was drawn one layer too low.** `girsa-app`
got the rules, the shell got the shapes, and shapes are where the drift is. It
does not produce two layers that both change per feature — it produces four
(`girsa-app` → `lib.rs` → `api.ts` → `main.ts`), and the co-change data confirms
it: those four files pair 15, 15, 13 and 9 times across 59 commits.

### The frontend, adjudicated

**~85% projection, ~15% product decisions, plus 312 Hebrew string literals across
19 TS files.** Where Rust hands over a *labelled list*, the window is genuinely
dumb and it is beautiful — `search.ts` draws the chip row with **zero knowledge
of what a chip is**. Where Rust hands over a struct with named fields, parallel
arrays, or raw keys, the window supplies the ordering, the labels and the
headings. Both patterns appear **in the same file**: `linksview.ts` draws lenses
from Rust (`:147`) and link-type Hebrew names from a TS lookup table with a
`?? kind` fallback (`:31`) — add a tenth edge type and a Hebrew UI silently
prints an English slug.

Two that should move:

- **`trouble.ts:989-1066`** — 21 regexes matching English `Display` prose from
  Rust to pick one of 21 Hebrew sentences. Every Rust error string is now
  load-bearing API, and the only test asserting them is on the TypeScript side.
  Rename `"no search index"` in Rust and both halves stay green while the reader
  gets a generic fallback. **`rewrite`:** an error *code* on the Rust side.
- **`mefarshim.ts:193`** — the entire information architecture of the mefarshim
  picker, four sections and three Hebrew headings, in TypeScript, next to
  `mefarshim.rs` which has 25 tests about this same list. The giveaway is
  `Mefarshim` arriving as four parallel arrays that only `listed()` knows how to
  weave. **`rewrite`:** `Mefarshim.listed: Vec<Listed>`. ~80 Rust lines in,
  277 TS lines and 315 test lines out.

Two verdicts against my own expectations:

- **Vanilla DOM is right and I would not overturn it.** Three runtime
  dependencies, no fossils. `pane.ts:616` measures selection offsets by asking
  the document for a Range's string length rather than summing run lengths —
  the only way to get a stable character offset across nikud, `<br>` runs and
  bidi reordering, and framework-hostile by construction. What `main.ts` needed
  was not React. It was a `Panel` type.
- **`styles.css` is the healthiest file in the repository.** 2,496 lines,
  maximum specificity 0-2-0, zero `!important`, zero ID selectors, theming
  through eight custom properties with explicit `data-theme` overrides in both
  directions. (Three dead properties: `--paper` and `--reading` are never
  defined; the lane sheet has no background as a result. One line.)

### `girsa-app` is one crate and should be at least two

Its `Cargo.toml` is the confession: the crate described as *"the shelf, tabs and
splits, and what keeps two columns together"* depends on `girsa-lane` (a 738 MB
embedding model), `girsa-ksav`, `girsa-cite`, and `zip 7.2` — the last because
`export.rs` writes `.docx`. `cargo test -p girsa-app` is the whole application:
any change to the docx writer retests the taxonomy.

The seam is obvious and unpaid. `beside`, `workspace`, `session`, `shelf`,
`arrangement`, `taxonomy` need `corpus`, `ref`, `hebrew`, `link`, `fix` and
nothing else.

**Related, and this one is a real crate-boundary tax:** `girsa-note` may not
depend on `girsa-fix`, so `since.rs` — 416 lines that exist *because* of the
split — counts unindexed corrections by calling `body.contains("\"when\"")` on
another crate's file and extracting a `u64` with
`line.split("\"when\"").nth(1).trim_start_matches([':', ' ', '"'])`. One crate
parsing another crate's format by string surgery, with `serde_json` sitting

### Three answers to "which seforim relate to this one"

- `Shelf::companions` — declared `commentary_on` + `companions.jsonl`
- `mefarshim::Marks::of` — `inbound.jsonl` + `taxonomy::stands` + a 12-edge threshold

Three data sources, three rules, three separate on-disk caches with three

that never appears in companions.

### The Ksav loop's most expensive decision

**The packet carries no character range.** `sending.rs:183` builds the ref from
`address_of(&from.id)`..`address_of(&to.id)` — the `from_char`/`to_char` that
decided *which words* are dropped. Spec §10.1 specified the field:
`"range": { "from": …, "to": … }`. `SourcePacket` does not have it, and §10.7's
"explicitly dropped" list contains only the quote-drift check.

So the promise that makes the whole two-app system worth building — *regenerate
quotes against a corrected edition without touching the prose* — **regenerates
the whole se'if for any partial selection**. The README's "only the highlighted
part goes" and §10.2's "citations stay alive" are both true and they contradict
each other at the regeneration step.

**Cost of reversal is now real:** every ref already written into every document.
Adding it to the ref syntax later makes old and new refs the same string shape
with different meanings. Adding it as a packet field means the ref is no longer
the whole address of the quote — two things that have to agree, which is exactly
the drift the shared-crate design exists to prevent. Carrying it was one optional
field on a struct both apps already compile, added before anything shipped.
**`rewrite`, and it is the most expensive `rewrite` in this document.**

**`delete`: `send_to_ksav`.** It calls the identical `girsa_app::send(...)` the
clipboard path calls and then POSTs the packet instead. It buys one keystroke:
Ctrl+V. What that keystroke costs, in `girsa-post`: a TCP listener, an endpoint
file, a per-run token, `create_new` + 0600 + a Windows ACL branch, a 0700 dir
fixup, a per-read timeout *and* a whole-exchange deadline, a `MAX_ANSWER` cap, a
deliberate no-CORS posture, and a three-state presence protocol. Every one is
correct and every one exists because a loopback port is a security surface. The
OS clipboard has none of it because the OS owns the channel.

**The desk earns itself as a *query* transport and not as a *transfer* one.**
`/cite` and `/quote` are pulls — Ksav asking a question and needing the answer
back in its own UI — and a clipboard is push-only with no reply channel.
`sending::quote()`, eleven lines, justifies the whole desk. It was built as both.

**`rewrite`: `who_cites`.** `citing.rs:60` answers *"which of your own documents
cite this place"* by iterating `Buffer::list(personal)` — `personal/ksav/*.ksav`,
and nothing else. Spec §10.4 promises this over *your own documents*. It is
delivered over the documents written in Girsa's toy editor. A `.ksav` written in
**the real Ksav — the app this entire pairing exists for** — will never be found.
And after `buffer_to_ksav`, which saves locally *and* POSTs, there are two copies
with no owner and `who_cites` answers from the stale one. **The change:**
`personal/documents.jsonl` — paths, mtimes, cached ref lists, rescanned when
mtime moves; the desk's `/document` is how rows get added. This region already
argued for exactly that shape, at length, for the link graph (`links.rs:16`).

### Notes are persisted twice, and the derived copy is what search reads

`Notes::write` writes the `.md`, then `shelve()` writes `work.json` +
`segments.jsonl`. `Notes::open` reads only the `.md`. `Shelf::read` and the index
build read only `segments.jsonl`. The module claims *"the file is the truth; the
graph is derived from it"* — it is derived eagerly, persistently, and **never
re-derived on open**.

So: edit a note's `.md` in vim (which the design explicitly invites) → `since.rs`
stats the mtime and tells you N notes aren't searchable → you rebuild the index →
it reads the stale `segments.jsonl` → the stamp is now newer than the `.md` →
the gap reports zero. **A closed loop where the "never a silent gap" machinery
reports success over a gap it created.**

### Where the next change hurts

Add one field to a search hit: `girsa-search::Hit`, `HitRow` in `lib.rs:406`,
**both** of its copy-paste construction sites (`:580` and `:725`), `api.ts`'s
interface, `search.ts`'s renderer. Five edits, two of them twins in one file, one
unchecked.

Add a fifth taggable noun (a scan, a link repair — both already personal-layer
nouns): `Tally` has four named fields, `Tags::of` takes four positional refs,
`export` takes five, `Shelf` exposes four accessors, `lib.rs` passes four twice.
Six signatures for one noun.

Add a sixth facet dimension that is a property of a *segment*: `SCHEMA_VERSION` 4,
a full 3.6 GB rebuild, plus `Fields`, `Tallies`, `Counts`, `Facets::of`,
`Facets::rows`, `narrow`, `exclude`, and the CLI flag table. Eight files, one

full on every call**. Typing two million edges is O(n²) file writes through an API
designed for hundreds of hand judgments. And `girsa-link-types.rs:93` builds the
facet cache from the *shipped* label, so a repaired type would be invisible to
search while visible in the sidebar — one question, two answers.

## Lens 3 — is the right code inside the shape?

Ranked by cost of leaving it.

**1. `hunt` iterates the wrong side of the join.** `girsa-fix/src/suspect.rs:344`
loops over the **hapax legomena** — 40–60% of any natural-language term
dictionary — and materialises ~`45L + 22` neighbour candidates per word, each a
fresh `Vec<char>` clone plus a `String`. On a multi-million-term Hebrew index
that is 10⁸–10⁹ allocations; the doc comment says *"a few million lookups."* Only
words with `count >= common_at` (default 10,000) can ever be the common side — a
few thousand terms. **Iterate those instead.** The result set is identical: the
grammar filter is symmetric by construction and a test asserts both directions.
Same answer, ~100× less work, one loop rewritten. This is the difference between
a batch job you rerun after every corpus update, which §7.3 asks for, and one you
run once and stop running.

**2. Every personal-layer store rewrites its whole file on every mutation.**
`Layer::add` → `save()` serializes **every** patch (`fix/lib.rs:542`). Same in
`Marks::add`, `Queries::save`, `Collections::save`, `Queue::decide`,
`Repairs::save`. The three-second test's own printed numbers are the proof:

```
18120 segments, no corrections yet:        75 ms
18120 segments, 1000 corrections already: 217 ms
```

142 ms attributable to 1,000 patches, linear — parse-all on open, serialize-all
on write. At 100,000 corrections that term is **~14 seconds**, against a 3-second
budget §7.5 calls a requirement. `three_seconds.rs:139` names this exact failure
— *"fast when it is empty and quadratic when it is not"* — prints the slope, and
stops at the one point where it still passes.

`Queue::decide` is worse and aimed straight at the feature's primary motion:
28,124 entries on the real corpus, rewritten in full per decision, in a product
whose pitch is *"being handed 4,000 ranked candidates."* **Append-only jsonl,
tombstones, compaction on open** — my sketch's one surviving win, and it makes
`Layer::merge` literally `cat`.

**3. `moved` — two multi-megabyte disk reads and a whole-session write, per
segment scrolled past.** `Beside::between` → `edges_between` → `read_to_string`
+ per-line JSON parse of **both** works' edge shards, constructed fresh on every
call (Berakhot's is 3.4 MB / 21,065 rows). Plus `state.save()` at `lib.rs:3542`
and `:3617` — `Session::save` serialises the whole workspace plus the positions
map for every sefer ever opened. `session.rs:295` says *"This one is saved on
every scroll"* as a statement of fact rather than a finding. `Beside` is
immutable while both panes stay open; it belongs in the LRU that already holds
`Marks`.

**4. `Repairs::apply` allocates 156,076 Strings to discover nothing was
repaired.** `repair.rs:428` maps `over()` across every edge; `over` → `about` →
`name_of` → `format!("{} → {}", …)` once per edge, then a `BTreeMap` probe on a
map that is usually empty. On every sidebar draw and every `Graph::work`.
`if self.by_edge.is_empty() { … }` — one line, cheapest win in the repository.

**5. `Graph::work` + `beside` is O(all edges in the work) per anchor.** Shulchan
Arukh Orach Chayim is 156,076 edges parsed and materialised to answer one hop; a
depth-3/width-8 trace rescans the full vector up to 73 times. The data is already
sorted-adjacent on disk — sort by `edge.from.from` once at load, binary-search
the run. No format change.

**6. `oversized::cuts` allocates the whole corpus's character count to answer a
question it usually doesn't need.** `oversized.rs:187` materialises an
8-bytes-per-char index of the entire text **then** checks whether it needed to.
4,994,812 of 5,000,545 segments are under threshold. Move the guard above the
collect: `text.chars().take(NAMES_A_PLACE + 1).count()`. Roughly 6 GB of
allocate-and-drop across an import. Not cheap — a measurable slice of the hour.

**7. `Job::did` is a linear `position` over a sorted Vec, once per embedded
segment.** `girsa-lane/src/job.rs:104` — 164M comparisons for Mishnah Berurah's
18,120 segments, and not finishable for a million-segment work. `wanted` is built
ascending. Binary search.

**8. `Words::open` parses the whole scan to answer about one page**, and the
Tauri layer calls it **twice** per page read (`scan_read_page` → `scan_reading`,
`scan_ocr_page` → same). `record` appends and never compacts, so superseded reads
are re-parsed forever. Reading page *k* of a 500-page masechta parses *k*
appended reads, twice. Hold `Words` in `State` keyed by slug — the mechanism is
already in the file for `marks`.

**9. `Bar::new` reads and parses 3.7 MB of lexicon twice, unconditionally**
(`bar.rs:153` → `citation.rs:194`), so every `girsa-index find` in every mode
pays for Citation mode. `OnceCell`.

**10. The snippet path moves megabytes to render 220 characters.** The crate
knows segments reach 1,275,307 chars and built `snippet.rs` to stop displaying
them — then `run` copies full text into `Hit.text`, `bar::results` clones the
whole page (`bar.rs:449`), `Hit::marks` tokenizes the *whole* segment to find
marks it discards, and `snippet` walks the text three times from byte zero. The
two `chars().count()` walks populate `Snippet::before`/`after`, which nothing
outside `snippet.rs` reads — they answer a boolean that is `from_byte > 0`.

**11. `Shelf::search` re-normalizes the whole 7,189-work catalogue per
keystroke**, with `query.to_lowercase()` recomputed *inside* the loop
(`shelf.rs:548`). The most-typed-into box in the application.

**12. Toggling *language* re-fetches every open sefer over IPC**
(`main.ts:648`) — including an 18,000-segment Mishnah Berurah — when the only
thing that changed is which of two title strings to print, and `titleIn` is a
pure function over data the window already holds.

**13. `SegmentIndex::load` reads the entire ~3 GB corpus to extract one field per
line** — and the doc comment at `index.rs:99` claims it is avoiding exactly this.
It avoids *retaining* the text; it still reads and lexes every byte. `girsa-link-import`
and `girsa-search::citation` both pay it.

**14. `nearest` is a full sort for a top-10** (`vectors.rs:297`), per slug per
query. And `Vectors::read` seeks on a `BufReader` per record, discarding the
buffer each time, so the "skip the vectors" pass reads the whole file anyway —
then `nearest` reads it a second time.

**15. `rank()` allocates two Strings inside the comparator** (`chain.rs:440`),
on the final tiebreak, so it fires on most comparisons of an O(n log n) sort.
`SegmentId` is already `Ord`.

**16. `pane.ts:262` is a write-then-read-then-write cycle inside one scroll
handler** — `extend()` appends up to 300 line elements and reads `scrollHeight`
twice, then `topLine()` loops `getBoundingClientRect()` over up to 400 children.
`{ passive: true }` keeps it off the scroll thread and does nothing about the
forced synchronous layouts. An `IntersectionObserver` deletes `topLine()`.

**17. Batch padding fights reading order and neither module notices.**
`model.rs:395` pads to the batch maximum, so a batch of sixteen containing one
512-token se'if and fifteen 20-token ones costs 16×512 through every layer. The
standard fix is sorting by length, which directly contradicts `job.rs:83`'s *"in
order, because a reader who starts the job and then opens the sefer is at the
front of it."* Plausibly a meaningful fraction of the thirteen days.

## What I tried to beat and couldn't

Ten sweeps, ten honest attempts. The ones that mattered:

**`Ordinal(Vec<u32>)` → a flat ordered key.** Eight bytes instead of a heap
allocation across 5M segments, machine compare instead of slice compare,
unbounded insertion between neighbours. It loses completely, and the reason is
the best thing in the design: `Ordinal::covers` is prefix containment, and prefix
containment **is ancestry**. An anchor written against `#32` before B12 cut it
into 128 pieces still names all 128. A LexoRank key minted between `7` and `8`
sorts correctly and has no expressible relationship to `7` — recovering "which
keys came from splitting this one" needs a side table, which is the redirect
table, which is the thing that doesn't exist. The dotted vector is not a
numbering scheme with ancestry bolted on; **the ancestry is the scheme.**

**`Together::Near` as a real unordered-proximity scorer** instead of the union
over every permutation (Heap's algorithm, capped at 5 words / 120 phrase
queries). It looks like the expensive way to get an exact answer. It loses on two
facts of the data model: a "position" here is not a term — an abbreviation
alternative is a *run* of words — so the scorer needs phrase match positions, and
tantivy's `PhraseScorer` exposes none; and `Contains`/`Letters` positions are
regex automata over expanded terms, which `RegexPhraseQuery` handles internally
and likewise exposes nothing. ~500 lines of the hardest code in the crate, on
`SegmentPostings` internals that move between tantivy versions, to speed up a
shape their own ceiling caps at five words. The permutation union is right and
the ceilings are its honest price.

**Collapsing the 100 IPC commands into ~8 fat sum-typed ones.** Failed on
arithmetic, not ergonomics: 23 of them are ≤8 lines and become ≤8-line match
arms; the fat ones stay fat (`find` is 93 lines because it maps five `Answer`
variants, and it is 93 lines as a match arm too). Merging relocates lines and
removes none, and it costs `generate_handler!`'s free per-command typed
deserialization. **The 100-command surface is fine. I was aiming at the wrong
seam, and the measurement is how I found the DTO layer.**

**`linkify`'s third rule** — *every level of the address must be a number or a
daf*. It's blunt and refuses `רמב"ם הלכות תפילה` and every named-section work.
The better design is to have `resolve` report how many words it consumed and
refuse a match that swallowed the start of another citation. It loses to the
repository structure: `resolve` is in `sefer-crates`, pinned `=0.5.0` by both
apps, and changing `Resolution`'s shape is precisely the breaking change the pin
exists to make expensive — for a rule one caller in one app needs.

**Cutting the README.** The split looks obvious: landing page (2.6%), build and
usage (4.5%), and 92% design rationale plus lab notebook. It fails on the fenced
blocks, because many of them are not measurements — they are **refusals**, the
literal wording a reader meets when the engine declines: *"the index at index
cannot be trusted"*, *"`^קדש$` is anchored"*, *"ברכות צט. is not a place on this
shelf"*, *"1 PDF on this shelf isn't searchable yet."* Those are the product's
differentiator made visible, and behind a link they are behind a link nobody
follows. A mechanical rule — *delete every paragraph naming a `Wnn`* — cuts
load-bearing prose along with the bookkeeping. I could not find a cut that keeps
the refusals and the remainders and drops the rest, and I am not going to claim a
split I couldn't make survive its own test.

**And two hypotheses I seeded that were killed, correctly.** The two
`taxonomy.rs` files are **not** duplication: `girsa-corpus`'s is a pure
`Work → shelf path` that `girsa-search`'s facets must share, and `girsa-app`'s
needs the personal layer, so the dependency direction forces the split. And
`keys.rs` / `keys.ts` is **not** duplication either: a synchronous `keydown`
handler cannot await IPC, and `keys.test.mjs:367` walks all 21 shipped defaults
asserting both sides spell them identically, with both columns hand-written so
neither proves itself. That is the best-argued duplication in the repository.

## What I'd want to know

The findings above assume things I can't read from the repository.

- **Is anyone but you going to run `girsa-import` twice?** If the corpus is a
