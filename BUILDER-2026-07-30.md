## B1 · The live preview is unreadable at 1366×768 ⚑ highest user impact

**Repro** (run it, watch it fail):

```sh
cd Ksav/ksav/app && npm run build
cd ../engine && cargo run --release --features embed-ui -- serve
# then, at 1366x768:
browse goto http://127.0.0.1:7878/ ; browse click "דברי תורה" ; browse screenshot /tmp/a.png
browse js "(()=>{const p=document.querySelector('#preview');return JSON.stringify({cw:p.clientWidth,sw:p.scrollWidth,sl:p.scrollLeft,dir:getComputedStyle(p).direction})})()"
```

Observed: `{"cw":680,"sw":860,"scrollLeft":0,"direction":"ltr"}`. An 860 px **RTL** page in a 680 px
pane with `overflow-x: auto`, and the container's direction is `ltr`, so `scrollLeft: 0` parks the
viewport at the *end* of every Hebrew line. `הקושיה` draws as `ה`; `המקורות` draws as `ות`.

**Build:**
- `#preview` gets `direction: rtl` when the document is RTL — or seed
  `scrollLeft = scrollWidth - clientWidth`. The first is one property and cannot drift.
- **Add a fit-to-width control** beside the existing zoom (`מרחק תצוגה`), and make it the default.
  Word fits the page by default; that default is why nobody ever meets this bug there.
- Assert it: a test that sets a narrow viewport, renders an RTL page wider than the pane, and
  checks the first *visual* line's leading run is at the right edge. It must go red today.

**Siblings:** every pane that can scroll horizontally over an RTL document — the source pane, the
prose pane, the review panel, the styles panel, the Girsa reading panes and the scan viewer. Check
each; say which you cleared and why.

## B4a · Girsa spells its sibling's name wrong, in six places ⚑ first screen

`Girsa/app/src/main.ts:512` and five siblings:

The application is **כְּתָב** — kaf-tav-bet, the Hebrew word for *writing*, which is its name in

every place either names the other, and say what you found.

This is thirty seconds of work and it is on the first screen, in a project whose whole premise is
that Hebrew writers deserve software that treats Hebrew properly.

## B5 · No Ksav diagnostic can name a line, because the type has nowhere to put one

**Cause:** `Ksav/ksav/engine/src/lib.rs:317`

```rust
pub struct Diagnostic { pub severity: String, pub message: String }
```

`diag_messages` (`:413`) receives `&[SourceDiagnostic]` — Typst's own diagnostic, which carries
`span` — appends hints and **discards the span**. So no consumer downstream can ever have one.

**Repro:**

```
#הדגשא[טעות]                  → unknown variable: הדגשא
#כותרת1[א   (unclosed)         → unclosed delimiter
#טבלה(עמודות: "שתיים")[א][ב]  → expected auto, relative length, fraction, integer, or array, found string
```

**Build, all four parts — this is one order because half of it is worse than none:**

1. **Put a location on the type.** `Diagnostic { severity, message, line: Option<usize>, column:
   Option<usize> }`. The prelude is prepended, so subtract its line count plus the `#show:` wrapper
   — a known constant in `assemble_source`, not research. Carry it through `/compile`'s JSON, the
   wasm path and the Tauri path.
2. **Show it.** The editor marks the line, and clicking the diagnostic jumps to it.
3. **Suggest.** `unknown variable: הדגשא` sits next to a 104-entry registry in memory. Emit *did
   you mean `הדגשה`?* — one edit distance, both scripts, the palette already does prefix matching.
4. **Stop leaking Typst's vocabulary.** *"expected auto, relative length, fraction, integer, or
   array"* names four Typst types a Ksav user has never heard of. Translate the argument-type
   family into the command's own words, bilingually, the way `server.rs` already does for transport
   errors (*"הבקשה לא נקראה — ייתכן שההעברה נקטעה · the request could not be read"*). **The team
   can write error messages; the compiler layer was never given the chance.**

**Rule to adopt and test:** every user-visible failure names (a) what failed in the user's words,
(b) the line or command they can act on, and (c) exactly one place to look.

**Siblings:** `app/src/brackets.ts` is a 260-line client-side linter with 37 tests that exists
*only* because Typst reports an unclosed `[` at end of file. Once locations exist, check whether
half of it can be deleted — **prefer deleting to keeping two mechanisms.**

## B6 · The timeout says the compile was stopped; the code says it wasn't

`Ksav/ksav/engine/src/server.rs:178` (doc comment): *"The overran computation **is not
reclaimed**."* `server.rs:218` (what the writer reads): *"…**והופסק** · …and **was stopped**."*

It was not stopped. It is running on a detached thread, holding one of `worker_count()` slots,

**Build:** say what is true — *"ההידור ננטש והוא ימשיך ברקע · the compile was abandoned and will
finish in the background"* — and show how many slots are in flight when one is refused.

**Siblings:** sweep both applications for a message in the past tense about an action that did not
complete. `heal`-shaped reporting is the classic; check every `catch`/`Err` arm whose message
asserts an outcome.

# TIER 2 — the shared crates

These compile into both applications. A defect here is a defect in both, and the security model of
the pairing rests on this crate being right.

## B8 · `Desk::drop` withdraws the token file and leaves the port bound

**Repro** (a standalone binary depending on `girsa-post` with `features = ["serve"]`):

```
endpoint file after drop : false     ← the file is gone
port 49694 still bound   : true      ← the listener is not
second desk port         : 49697
first desk STILL bound   : true      ← two live listeners, one token file
```

**Cause:** `sefer-crates/crates/girsa-post/src/desk.rs:147`. `serve()` clones the `Arc<Server>`
into a detached thread looping on `incoming_requests()`; dropping the `Desk` drops one `Arc` and
the thread holds the other. The comment there says *"The file outliving the listener is exactly
what `Presence::Stale` exists for"* — **the code produces the inverse.**

Every `Desk::open` leaks a bound loopback port with a live token that still answers `/health` and
every errand. The whole security model is *"a token in a file only you can read"*; a listener whose
token is in no file is **outside that model and cannot be revoked.**

**Build:** hold the `JoinHandle`; `Drop` calls `Server::unblock()` and joins. Test: open, drop,
assert the port refuses a connection. Fix the comment to describe what happens.

## B9 · The token file is created world-readable, then chmodded

`girsa-post/src/lib.rs:154` — `fs::write(&path, …)?; restrict_to_owner(&path)?;`

On Unix the file is born `0o666 & !umask` (0644 on a stock system) and there is a window before
`set_permissions(0o600)` in which any local user can read the token. The parent is `create_dir_all`
→ 0755. The module doc says the token is *"published in a file only the user can read"*.

**Build:** `OpenOptions::new().mode(0o600).create_new(true)` (with an unlink-and-retry for a stale
file), and 0700 on the directory. Test on Linux that the mode is never observably 0644.

## B10 · The desk caps requests at 1 MB and the client caps responses at nothing

- `lib.rs:297` — `reader.read_to_string(&mut answer)?` with no limit, guarded only by a 400 ms
  *per-read* timeout. Composed with B8, a process that takes a released port can drip a byte every
  300 ms and grow the caller's `String` without bound — while `presence()` runs *"while a reader is
  looking at a menu."*
- `desk.rs:178` — `body_length().unwrap_or(0)` means a chunked body with no `Content-Length` passes
  the 413 check and is then silently truncated by `take(MAX_BODY)`. **Refuse it or accept it; do
  not half-accept it.**

**Build:** mirror `MAX_BODY` on the read side, add a total deadline as well as a per-read one, and
refuse a body whose length is unknown *or* over the cap.

## B10a · The gematria ceiling is reachable, on 43,076 real addresses

`girsa-ref/src/numerals.rs:161` gives up at 1000 and switches alphabets without saying so:

```
to_hebrew(999)  -> תתקצ"ט        999   מעדני יום טוב על ברכות סימן תתקצ"ט
to_hebrew(1000) -> 1000         1000   מעדני יום טוב על ברכות סימן 1000
```

I assumed this was unreachable and measured it instead: **43,076 of 5,000,545 corpus addresses
(0.86%) carry a component ≥ 1000**, beginning at `girsa:bavli/maadaney-yom-tov-on-berakhot/1000`.

**It fails safe** — `numerals::parse("1000")` is `Some(1000)`, so the printed form still resolves
back and the crate's governing round-trip test still holds. That is the only reason this is not a
Tier 2 order.

**Build:** Hebrew's thousands convention (`א׳` and a geresh) — or refuse above the ceiling and say
so. Do not silently switch alphabets inside a citation in a formatter whose whole promise is *"how
it is written in a sefer"*. Extend the round-trip test to the four-digit range in the same change.

## B11 · Deep links: case-sensitive scheme, lossy decode

- `link.rs:56` — `url.strip_prefix(app.as_str())`. RFC 3986 makes schemes case-insensitive;
  `GIRSA:bavli/berakhot/2a:1` out of a PDF viewer that normalises case is refused as *"a
  misconfigured machine"*. Compare case-insensitively.
- `link.rs:127` — `String::from_utf8_lossy` turns `%FF` into U+FFFD **silently**, so a corrupted
  link becomes a *different, valid-looking* ref instead of a refusal — in the crate governed by
  rule 4 above. Return `None` on invalid UTF-8.

**Siblings:** every other place either application parses something the operating system or another
program handed it. Name them.

The whole architecture rests on *"each record carries its own id, so every anchor still names the

## B13 · Girsa has no settings ⚑ bar #2

**Build:** a settings panel with, at minimum — font family and size for Hebrew and for Latin, line

**Look at Ksav's settings drawer** (`Ksav/ksav/app/src/main.ts:1321`) — 17 document settings, a
reset-to-defaults, and a per-document custom `#let` preamble. **Whatever it knows, this panel

## B22 · The rest of the personal layer

## B27 · A shared document's own commands compile but do not autocomplete

| site | reads |
|---|---|
| `app/src/compile.ts:57` | `runtime.currentDoc?.customCommands ?? settings.customCommands` |
| `app/src/main.ts:419` (`userCommandNames`) | `settings.customCommands` **only** |

`compile.ts` states the intent: *"A document that carries its own custom commands … uses those, so
a shared sefer compiles for its reader."* It does. But open that sefer and `#` completion offers
**your** commands, not the document's — and if you have a global `#דגש` meaning something else, the

`userCommandNames()` has exactly **one** caller: the command palette (`main.ts:1741`) never calls
it, so a user-defined command is invisible there in every case.

**Build:** one function that answers *what commands does this document have*, read by the compiler,
the completions and the palette. **This is the "every layer that carries the same value" family;

## B28 · `#נוסחה` is the one command that breaks the bracket convention

## The single idea behind all of this

Every headline number in these three repositories came back **exact** when it was re-measured.
7,189 works and 5,000,545 segments, to the segment. 79 hits for `יתגבר כארי`. 61 places for the
Mishnah's own line. 104 commands, 10 templates, all compiling. Half a second over five million
segments. That is real engineering and it is rare.

And the button on the first screen labelled *Start blank* does not start blank, the preview is
unreadable on the laptop most people own, no error message can name a line, and your own writing is
invisible to the search that is the reason you came.

**The gap in this project is not between what it does and what it claims. It is between what it
does and what a stranger can find.** Every order in Tier 0 and Tier 1 exists to close that gap, and
they are hours of work sitting in front of years of it.

So for every change you make, ask the same question the Grader will:

> **If a bochur opened this for the first time tonight, would he still be using it in the morning?**

Build for that. That is the whole job.
